# 细分选项网页模式

先读取`references/category-taxonomy.md`。网页分类必须与普通 Markdown 表格逐字一致，不得使用网页专属别名。

## 触发条件

用户提到“细分选项”“展开更多可能性”“详细列表”“100 条”“网页版”“概率页面”，或要求按概率交互筛选时，默认生成实际 HTML 文件，而不是只给 Markdown 表格或 HTML 代码块。普通简短问答仍使用默认单表。

## 必备要求

- 页面主题与唯一 `h1` 为“这次事件的概率”。
- 展示当前事件、必要假设和概率估计性质。
- 默认包含 100–200 条有区分度的可能性；用户要求扩充时按用户指定的倍数增加，可超过 200 条。构建器支持 100–500 条。
- 分类统一写成“正向·小分类”或“负向·小分类”，方向在前，单一主题在后。
- 正向行位于上方，按百分比从高到低；全部负向行随后，按百分比从低到高。
- 负向数量必须是正向数量的 1.20–1.35 倍；构建脚本会拒绝不符合 20%–35% 负向差额的数据。
- 详细页面必须包含若干多层因果链负向情景，按`causal-chains.md`构造，并给出最早阻断点。
- 提供专门的概率选择器，所有选项和结果均以百分比显示。
- 保留下拉列表选择，并提供“列表选择／滑块选择”切换；滑块模式用最低和最高概率筛选范围。
- 极小概率可以使用 0.001%、0.01% 等显示值，必须保留非零数字，不能格式化成 0%。
- 表格最右侧为紫色百分比条，并显示具体百分比与证据把握。
- 页面明确写出“本项目及其所有生成内容仅供娱乐，不构成任何专业意见、决策依据或行动建议。内容由 AI 基于假设生成，可能存在错误、遗漏或偏差，使用者须自行核实、独立判断，并自行承担使用、参考、依赖或传播本项目及生成内容所造成的一切直接或间接后果。开发者 PT-dove 不承担任何法律、经济或其他责任。”。
- 保持简洁，不自动播放、不自动跳转、不自动打开教程或弹窗。
- 单文件离线可打开，不依赖 CDN、外部字体、框架或网络请求。

## 手机端强制适配

不能把桌面表格按比例缩小后交给手机用户。模板在 820px 及以下切换为专门的事件卡片布局：

- 每行情景变为纵向卡片，隐藏桌面列宽配置，所有内容纵向排列，不出现横向滚动。
- 筛选器、列表/滑块切换、搜索和重置按钮使用单列布局。
- 标题使用流式字号，320px、375px、430px 等窄屏不得溢出。
- 输入框使用至少 16px 字号，降低手机自动缩放干扰。
- 按钮、选择器和滑块触控区域至少 44px 高。
- 百分比条保留在每张卡片末尾，数字、依据和应对完整可见。
- 支持安全区域边距，手机横竖屏切换后仍可使用。
- 桌面端继续保留表格；移动端的卡片化只改变呈现，不改变数据和排序。

## 分类规则

正确示例：`正向·娱乐`、`正向·社交`、`负向·健康`、`负向·法律`、`负向·平台`、`负向·账号`、`负向·极端`。

- 方向只能是`正向`或`负向`。
- 小分类只表达一个问题领域，不使用“法律/合规”“隐私/账号”等斜杠组合。
- 法律问题写`负向·法律`，账号或平台处罚写`负向·平台`，网络账号失窃写`负向·账号`，不要混成一类。
- “极端”只用于极低概率、高影响场景，不与方向冲突。
- 分类排序仍由概率决定，不因小分类不同而改变正负向区块内的顺序。

## 紧凑数据格式

创建一个 UTF-8 JSON 文件，结构如下：

```json
{
  "language": "zh-CN",
  "event": "用户的事件",
  "assumptions": "时间窗口、条件与未知信息",
  "items": [
    ["正向·娱乐", "具体事件", 65, "中", "依据或触发条件", "建议", "中"],
    ["负向·法律", "具体事件", 5, "低", "依据或触发条件", "建议", "低"]
  ]
}
```

`language`必须与安装选择一致。英文数据使用`"language":"en"`、`Positive·Subject`和`Negative·Subject`，并将事件、依据、建议、影响和证据把握全部写成英文；中文数据使用`"language":"zh-CN"`。构建脚本会复用同一模板翻译界面，不维护两套 HTML。

每项严格使用 7 个位置：

1. 分类：`正向·小分类`或`负向·小分类`。
2. 具体事件：避免只改几个字的重复场景。
3. 概率：0–100 之间的数字，不带 `%`；使用粗粒度值，极小概率必须明确标注为低把握情景估计。
4. 影响：`低`、`中`、`高`或`极高`，方向由分类前缀决定。
5. 依据或触发条件：区分一般机制、假设与条件场景。
6. 建议：正向事件写机会捕捉，负向事件写预防或应急。
7. 证据把握：`高`、`中`或`低`。

百分比是用户要求的显示形式，不代表拥有真实统计。普通场景使用粗粒度档位，避免 13.73% 之类的伪精确数字。极小概率仅用于说明“极罕见但可设想”的条件场景，不伪造统计来源。

## 内容扩展方法

按机制分批构思，再统一去重：

1. 正向娱乐、成就、社交、机会、成长和便利。
2. 身体健康、作息与人身安全。
3. 情绪、认知与行为。
4. 财务、财产与消费。
5. 法律、平台、账号与隐私，分别作为小分类。
6. 社交、家庭、学校与职业责任。
7. 设备、环境、时间与运营。
8. 延迟后果、连锁后果和极小概率高影响事件。

扩展时优先增加新的机制和明确条件，不要通过替换同义词、机械排列组合或捏造事实凑数。扩充后的总数不得少于用户要求的倍数。

## 构建

```bash
python scripts/build_probability_page.py data.json output.html
```

仅校验数据：

```bash
python scripts/build_probability_page.py data.json --check-only
```

脚本读取同目录上级的 `assets/probability-page-template.html`，自动验证数量、七字段格式、正负向分类、单一小分类、概率、影响、去重与排序，然后把数据注入模板。不要在聊天中粘贴完整 HTML。

## 验收

- JSON 通过脚本校验，数量达到用户要求，且负向比正向多 20%–35%。
- 所有分类均以`正向·`或`负向·`开头，小分类不含斜杠。
- 默认顺序严格符合正向降序、负向升序。
- 下拉列表的范围和具体百分比筛选可用，滑块模式可按最低与最高概率筛选。
- 极小概率显示为非零百分比，切换、重置和空状态可用。
- 右侧百分比条与数字一致，无脚本注入或外部依赖。
- 320px、375px、430px、768px 和桌面宽度下内容可阅读；820px 以下必须为卡片布局，无桌面表格横向滚动，控件可触控和键盘操作。
- 免责声明、假设、事件名称和总数可见。
- 最终回复只提供文件、条目数和必要说明。
